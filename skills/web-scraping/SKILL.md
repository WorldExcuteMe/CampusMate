# 复杂网站信息获取（code-as-tool）

## 何时用
- 需要从**没有公开 API** 的校园/教务/学院网站批量获取信息（竞赛通知、讲座、名单、课表、公告）。
- 页面依赖 JavaScript 渲染、分页、登录态、动态参数，或需要解析 HTML/JSON/PDF/Excel。
- 单页目标可能人工可读，但批量/多站点/需要长期重复时，优先写代码。

## 流程（必须按顺序）
1. **探测**：先用 `web_fetch`/浏览器只读能力抓 1 个样本页，观察真实结构（静态 HTML？JS 渲染？JSON 接口？分页参数？登录重定向？）。
2. **小样本**：写最小脚本（`workspace_write` + `workspace_run`，建议 Python/Node）解析 1 页，打印结构化结果；确认字段与编码。
3. **校验**：与页面可见文本人工一致（标题、日期、数字）；记录来源 URL；对缺字段记录 `null` 而不是猜。
4. **批量**：加分页/循环、限速（每请求间隔 ≥300ms）、去重（URL+关键字段）、断点（已抓取列表落盘）。
5. **二次校验**：抽样回读 2–3 条与页面比对；统计成功/失败条数；失败分类（403/超时/结构变化）。
6. **交付**：输出 JSON/CSV + 来源清单 + 失败清单；报告里说明"哪些没抓到、为什么"，不编造缺失数据。

## 硬性规则
- 只抓**公开可读**页面；需要登录时使用用户已授权的本地浏览器会话，不绕过认证、不伪造身份。
- 遵守站点 robots 与合理频率；不并发轰炸；遇到 403/验证码→停止该站并说明。
- 脚本默认放工作区 `scripts/`；产物放 `data/`；脚本内写清目标 URL、解析字段与容错。
- 依赖安装前先检查已装（`python -c "import ..."`）；安装使用项目内虚拟环境或用户目录下限定作用域。
- 解析失败两次后换策略（换接口/换解析方式/换页面来源），不要用相同参数重试第三次。
- 最终交付必须包含：数据文件、字段说明、来源 URL、抓取时间、失败清单与未核实标记。

## 常用骨架
- HTTP：`urllib`/`requests` + 超时 + 重试（2 次，指数退避）；
- HTML：`selectolax`/`BeautifulSoup`（优先真实标签结构，不依赖 class 随机名）；
- JS 渲染：先找页面 `__NEXT_DATA__`/`application/json` 接口；必要时用受控 Playwright 脚本（只读、域名白名单）；
- 文件：`openpyxl`/`pdfplumber` 解析表格与 PDF，保留原始文件以便复核。
