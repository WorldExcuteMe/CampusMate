## 1. 修复实现及业务影响

| 原问题 | 根因与改动 | 验证与边界 |
|---|---|---|
| 截止日期更正产生两条 Inbox | 新建 identity 包含截止日期，却没有明确更新操作；增加 owner+itemId 更新、列表定位和旧 save 的唯一匹配兼容 | 保留原 id、原文；确认后的记录不自动改；同名不同场次仍可分别新建。memory 与 PGlite 实际 SQL 回归，不等于云 PG/RLS 验收 |
| 搜索后回复缺少可追溯 URL | 年份被误切为实体、泛检索接受日历等偏题结果、多来源摘要路径不适合仅列官网请求 | 主题过滤、逐候选核对、有界批量读取、收窄到用户请求的字段；不放松原文引用门槛。URL 断言通过不代表任务完整成功，仍抽查实际状态 |
| 只要预览却开始完整策划或写文件 | 全文文档意图过宽，写入守卫未覆盖文档工具 | 预览/等待确认优先，统一按工具写权限拦截；“不要保存到 Inbox，只生成 Word”保留文档意图 |
| 后续轮次长时间排队、零模型调用 | 暂停任务是会话顺序屏障，新轮次仍被接纳 | 新轮次返回明确 409，原 turn 幂等重试保持；恢复或取消后再继续。UI 对暂停/待处理任务提供说明与取消，旧失败记录仍可用新消息继续 |
| 1 token 预算仍先花数千 tokens | 只在模型返回后核算 | Adapter 提供输入估算，发送前检查并预留输出；不足时零请求暂停。未知估算的注入 transport 保留实际用量后置保护；token 估算和货币费用不是精确账单 |
| 简单步骤反复启动高思考及长回答 | 标题/正文中的“核验”等名词误当本轮行动 | 按当前动作分阶段，增量小步骤提示限范围；显式 high 仍有效。提示词不能保证字数，不以此代替实际验收 |
| 正在输出仍在 180 秒截断 | 连接/无响应时限被当作整个活跃 SSE 的固定总时限 | 仅在调用方提供任务截止时，正文/工具参数/内部思考增量可刷新空闲时限；受任务截止及十分钟单请求上限限制。空心跳不续命，取消仍生效；非流式、重试和无任务截止请求保留原时限 |
| 失败后丢失已完成轮次，首字计时失真 | 全案结束才存观察；空 role 帧被当首字 | 逐轮/逐例落盘，超时仅给一秒协作清理但仍判失败；TTFT 忽略空帧。未放松工具 index 协议；一次旧协议错误未复现，不能声称根治 |

产物检查新增 `artifact_export`：实际导出、按格式复读、正文/标题要求、授权下载得到相同哈希，并保存收到的真实字节。检查不证明排版、所有事实正确或所有下载器兼容。

## 6. 自我反驳与未验证项

- “回复有URL”过弱：若只读到两项正文却要求三项，不能称完整成功；真实样本里两个ICPC地区站仍有品牌多样性限制。
- “提示词要求简短”不能修复硬超时：已用两次真实失败证伪，增加有界进度时限，不延长评测阈值来抹掉失败。
- “脚本正确”不能说明模型会选对工具：固定 live 与多轮 live 独立运行。
- “新增通过率≥90%”不能自行变成固定计分通过率：AI生成集保持探索性，必须有人挑选后才能晋升。
- 当前未证明：跨轮编辑已有文档版本、多轮图片记忆、人工审批后真实模型恢复、取消/刷新完整UI路径、云PG/RLS、其他用户自带模型端点。
- 金额计价缺失，ledger的`costUsd=0`不是免费API证据；KV收益没有足够对照样本，不宣称优化幅度。
- 单请求最多十分钟仍可能过长，且慢模型可能无法在原用例时限内完成；真实长任务结果决定是否达标，不能靠无限等待。
