# CampusMate 本机自托管与评委展示

2026-11-18。现有本机工作区、评测记录与应用路由为方案依据。开发和评测采用独立工作区。本文件记录产品方向、模块合同和验收顺序。

## 两个入口

| 入口 | 使用者与目标 | 身份、数据与运行时 |
| --- | --- | --- |
| 本机 CampusMate | 每人部署一个自己的 Web Agent，用浏览器使用 | 首次启动创建或认领本机账号，随后登录自己的实例。工作区、会话、文件、配置和业务数据存本机；远程 LLM 由用户选择，访问本地材料受单独授权。开发机能运行 Worker，浏览器刷新或进程重启不应丢任务状态。 |
| Qoder Sites 公开展示 | 评委打开网址即可体验和检查证据 | 无需注册、不收集密钥。使用合成数据、可重置的浏览器状态、脱敏的真实 Headless 回放和预生成工件。仿真、真实回放、联网实跑三种状态明确标注。静态版可独立打开，私有实例连接信息留在本地。 |

[Qoder Sites 官方说明](https://docs.qoder.com/qoder/sites)显示静态发布可用，部分方案支持托管存储。公开演示选静态优先，便于无密钥、无中心服务地验收。六个参考作品均通过只读 HTTPS 请求取得成功状态与页面标题，这里只取其呈现目的和用户提供的说明作为参考。

## 架构演进

| 层 | 既有能力与缺口 | 顺序与验收 |
| --- | --- | --- |
| 本机启动与存储 | `main-local.ts` 同源提供 SPA、API 和 Worker，绑定回环；PGlite 已复用 Postgres 迁移。PGlite 目前被标成开发依赖，生产安装会省略本机启动必需的模块。 | 先修复生产安装。随后提供工作区医生、磁盘和数据库健康、备份导出与恢复、版本升级后的迁移检查。全新目录、生产安装、重启和旧库升级均实测。 |
| 登录与数据归属 | 本机 HTML 目前注入工作区所有者临时 JWT。云端入口已有 Supabase Auth、RLS 和账号缓存隔离。 | 保留单机与现有部署兼容入口。把本机所有者认领变为显式一次性流程，后续用同源 Cookie 会话。以本机登录重登、退出/撤销、旧数据归属、两个账号隔离为验收；完成多账号授权前不把本机服务开放到局域网。 |
| Agent 核心 | Worker、预算、检查点、调用日志、审批、恢复、独立 Evaluator 均存在。现有长程夹具已走完 10 轮并暴露标题交付问题。 | 保留现有任务状态和会话协议。补齐计划阶段出口、已完成交付收据、错误重试边界、网络等待归因和跨轮可复用状态。用同模型基线看成功率、耗时、手工介入和缓存；不以通过一题为由更换整套工作流。 |
| 连接器和工具 | 本地工具已通过注册表按任务注入，授权源有分页、记录完整性与预览。 | 以官方 MCP TypeScript Client 做一个受控连接器试点。先用只读合成校务数据验证发现、schema、超时、禁止未授权动作与结果保存。不同传输走同一权限层。 |
| 公开证据和诊断 | 现有事件流和报告目录有模型、工具、检查、工件。 | 用现有数据先做时间线、评分和来源回读。需要跨进程观察时用 OpenTelemetry 生成本机 OTLP，默认不记录模型正文、授权数据与密钥。 |
| 错误与版本管理 | Node24、React/Vite、Playwright 和文档渲染已有工作路径。 | 避免同时迁移 UI、登录和编排。每次引入依赖固定版本、记录许可与维护情况，需能通过冒烟/基线、对旧数据验证和局部回滚。 |

## 开源项目选型

| 项目 | 用途 | 决定 |
| --- | --- | --- |
| [PGlite](https://pglite.dev/docs/) | 嵌入式 Postgres 给单机复用现有数据契约 | 已在用。本轮修正运行依赖分类与锁文件，不新建平行数据库。 |
| [Supabase Self-Hosting](https://supabase.com/docs/guides/self-hosting) | 兼容已有业务和账号的自托管落点 | 保留兼容路径。CLI 本地开发栈与正式自托管分开验收。 |
| [Better Auth](https://better-auth.com/docs/concepts/session-management) | 本机持久 Cookie 会话、撤销和注册 | 候选。先在独立工作区验证 Node 同源接入、数据库兼容与已有所有者迁移，避免同时持有两套生效的登录源。 |
| [MCP TypeScript SDK](https://ts.sdk.modelcontextprotocol.io/v2/get-started/first-client.html) | 标准化第三方工具查询与调用 | 下一阶段最先试点的新依赖。通过显式配置、审批和受限进程管理接入，工具输出按外部数据处理。 |
| [Ajv](https://ajv.js.org/strict-mode.html) | 复杂第三方工具 schema 的编译和诊断 | 现有校验需要工作正常。MCP 试点出现已有子集不覆盖的 schema 再引入，关闭自动类型转换和字段移除。 |
| [OpenTelemetry JS](https://opentelemetry.io/docs/languages/js/) | 统一请求、工具和恢复过程的追踪 | 先用事件合同完成评委可读时间线。增加跨进程采集时采用其标准字段和本机导出。 |

## 评委试玩路径

首屏一个主入口「打开演示工作台」。三个场景按实际成果组织，进度上可直接查看已完成的示范。靠近主按钮提供「查看实跑证据」和「本机安装」入口。保留键盘操作、手机布局、错误状态和没有模型时的完整演示。

| 场景 | 评委动作 | 可见结果与全模块串联 |
| --- | --- | --- |
| 处理一周通知 | 选模拟 QQ 或微信导出或高校公告，检查去重与截止更正，再确认进 Inbox | 智能体工作台展示原始范围和工具过程。信息中心读回原文和更正记录，可信核验显示来源与未知，今日显示临近截止，任务与目标提供可确认的后续行动。 |
| 导入全学期课表 | 切换 CSV/ICS/模拟门户，查看完整性与冲突，确认导入 | 课表周视图据实回读至少两周和一次例外周。今日读取下一节，个人资料说明学校/学期匹配。设置可以查看本机工作区、连接器授权和模型传输范围。 |
| 从机会到可交付策划 | 筛选机会、验证要求，写规划并检查导出 | 机会中心呈现来源与适合度，成长中心把已确认的建议形成目标或计划。任务与目标记录下一步，文档真实工件支持 Markdown、DOCX、PDF，证据页可检查内容和摘要。 |

首页在每条场景中都要展示具体动作后的页面变化和能验证的结果。发布前用全新浏览器验证免账号入口、深链接刷新、移动端、导出下载、重置、断网和超时状态。隐私边界、当前数据类型和本机安装说明与成果同页可查。评委使用公开入口时不需要连接开发机。

## 交付次序

1. 完成当前回归，保留真实运行及横向表。本轮兼顾修复已证实的本机安装问题。
2. 完成本机账号、工作区、恢复和业务数据隔离的安装闭环。用同一套原生页面做演示入口及合成数据适配。
3. 扩大通用原版 benchmark，并在 Radeon Cloud 用同一个本机密钥跑冻结矩阵。每个版本留下成功率、重复稳定性、时间、费用、缓存和权限证据。通用型能力达标后扩大校园连接器覆盖。
4. 做三个演示端到端路径及全页面能力索引，验收图文、回放和下载。之后由 Qoder Sites 构建并发布经核验的公开展示版本。

## 本轮落地验证

生产锁文件中 PGlite 从开发依赖移入运行时依赖，版本保持 0.5.16。最小生产安装实测可以初始化 PGlite 和 pgcrypto，查询生成 UUID；没有把此项扩大为完整安装包验收。前端只在本机工作区将受限课表预览链接交给日历，覆盖历史链接和拒绝附加参数路径。

只读检查六个 Qoder 站点得到 HTTP 200。三站在 HTML 中可直接确认交互入口。创跃展示免 Key 演示入口，社交场景按用户要做的事给快捷入口，物理画布提供工作台与运行架构视图。其余站的交互细节、账户流程和模型运行未验证。演示规格据此强调免账号入口、按任务组织体验和可检查的执行证据。
