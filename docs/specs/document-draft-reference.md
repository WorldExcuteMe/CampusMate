## 契约

用户明确要求把上一条已完成正文、或当前显式【文稿开始】…【文稿结束】原稿创建/导出为文档时：Runtime提供document_create的短参数变体`title + fromDraft=true`，服务器从当前已授权会话材料编译受限heading/paragraph/list/table结构。其余工具不变。正文不经模型二次改写；仍由模型选择调用、检查、导出并返回真实链接。没有合适原稿、只预览或待确认时不提供变体。

解析仅覆盖此受限文本子集；代码块和图片等富内容回退既有路径，不静默丢弃。保留所有文字/链接，不宣称核实外部事实。不给模型任意消息ID/owner选择。原稿不接受系统消息、工具输出、未完成工具指令或失败提示。

工具执行前解析短引用，随后继续使用原参数校验、权限、预算、取消、幂等、事件和DocumentService/真实下载。toolMeta与executeTool收到同一已解析参数，记录来源文本SHA256；原全局工具schema不变。

## GWT与验证

1. 已有正文+明确创建 → 原生与JSON协议均可用短参数；四章/列表/表格/文字保留，工具实参符合原schema。
2. 预览/未确认/不存在原稿/系统或工具材料 → 不提供引用、不执行无blocks的调用。
3. 其他任务 → 全局schema、既有工具行为保持；引用不会增加读其他session/owner的能力。
4. 同一toolMeta与execute参数 → 幂等指纹不因引用解析失配；调用/观测仍配对。
5. 真实API先定向复现导出阶段，再跑原10步任务、固定集两次、留出/Gate。新定向用例保持exploratory；不冒充完整10步连续验收。
