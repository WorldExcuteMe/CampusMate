# CampusMate 前端设计系统 v1（2026-11-20）

> 目标：把当前"AI 生成感强、信息齐但重点散"的界面，重构成一套**注意力友好、可延展、有自己气质**的
> Agent 产品视觉系统。先定 token 与层级，再逐组件/逐页面落地；所有页面（对话、设置、信息中心、机会雷达、
> 日历、画像）共用同一套规则。

## 0. 调研结论（设计参考与"AI 默认审美 tell"）

**参考对象**（不是照抄，是提取规则）：
- Agent 对话类：DSH `ui-chat/ui-conversation`（三栏、事件流、工作步骤四级、上下文仪表）、
  Claude Code / Codex 的"过程即产品"（thinking 折叠、工具卡、终端卡）、ExodeUI 的 agentic UI states 清单。
- 工具/产品类：Linear（层级与留白）、Raycast（紧凑列表与快捷感）、Vercel Geist（字体与边界克制）、
  Arc（个性但不喧宾夺主）、Ant Design 中文字体排版（中文行高 1.5–1.8）、Material 3（语义 token）。
- 设计方法：Anthropic frontend-design skill（**先出 token 计划，再写代码；对照 AI 默认审美 tell 修订**）、
  Google `DESIGN.md` 规范（把视觉身份写成机器可读 token 文档）、shadcn 语义 token 分层、
  OKLCH 感知均匀色阶、WCAG AA 对比度。

**要主动避免的"AI 默认审美 tell"**：紫蓝渐变/发光泛滥、玻璃拟态、一个大 hero + 卡片瀑布、
圆角不统一、字号层级过多、emoji 当图标、每个区块都加边框/阴影、把元数据做得和正文一样重、
动效过多或无意义动画、深浅色不是同一套语义。

## 1. 设计原则（按优先级）

1. **注意力优先**：任何一屏只有一个"主角"（当前任务/当前对话/当前主操作），其余降级为支撑信息。
2. **层级不超过 3 级**：字号/颜色/布局权重最多 3 档可辨；第 4 档内容默认折叠。
3. **内容优先于容器**：能用留白、分割线、背景层解决的不加卡片；卡片只用于"独立对象"（会话、工具调用、文档、事件）。
4. **过程可读但不喧闹**：Agent 的思考/工具/终端过程默认收拢为一行摘要，按需展开；运行中给出明确状态点。
5. **一致的动作位置**：主操作固定在内容右下/底部；导航、设置、权限的位置全站一致。
6. **本地优先的气质**：可信、安静、像"自己的工具"而非营销页；装饰性图形只出现在空状态/品牌位。
7. **可访问性底线**：对比度、焦点可见、键盘全路径、命中区 ≥32px、`prefers-reduced-motion` 尊重。

## 2. 视觉方向（三选一，推荐 B）

| 方向 | 描述 | 优点 | 风险 |
|---|---|---|---|
| A. Ink & Aurora（现状收敛） | 保留深蓝紫 + 极光点缀、0.75rem 圆角、柔和 glow | 改动最小、已有 token | 正是"AI 默认审美"，显得模板化；紫蓝发光容易疲劳 |
| **B. 石墨编辑风（推荐）** | **中性石墨/纸白 + 单一强调色（青绿/琥珀二选一）**；正文黑/白，颜色只用于状态与 agent 活动；小圆角 8–10px；几乎无渐变/无 glow | 像 Linear/Raycast 的工具感；层级清晰、长期耐看；中英文都稳 | 需要一次性重置 token 与部分组件样式 |
| C. 温暖校园风 | 米白/纸张底 + 墨绿 + 少量暖橙 | 学生亲和力强 | 深色模式难统一，Agent 过程类信息偏"软"，专业感弱 |

**推荐 B+（已确认）：石墨工具风（VS Code 式纯色，无青绿）**
- 基底：中性石墨/灰阶，**不用青绿强调色**；强调色用工具类产品最常见的系统蓝（Light `#007ACC` / Dark `#3794FF`），
  只用于主操作、选中、链接、焦点；状态色（成功/警告/危险/信息）仅用于状态。
- 表面：靠 1px 边框 + 灰阶分层（surface-1/2/3）区分，不用阴影堆叠；浮动层用一层轻阴影。
- 圆角：`4/6/8/10`（默认 8）；**禁止全站 0.75rem 大圆角**。
- 无渐变、无 glow、无玻璃拟态、无装饰性彩色；图标用单色线性（Lucide），不用 emoji。
- 字体：`Inter`（西文）+ `PingFang SC / Noto Sans SC / Microsoft YaHei`（中文）；等宽 `JetBrains Mono / Consolas`。
- 气质：像 VS Code / Linear 的工具——信息层级靠字号、灰阶、留白和 1px 边框，而不是颜色和阴影。

### 3.2 字体与排版（中文优先）

| 角色 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| Display | 24/1.3 | 600 | 设置页/首页大标题（每屏最多 1 个） |
| H1 | 20/1.4 | 600 | 页面标题 |
| H2 | 16/1.5 | 600 | 区块标题 |
| Body | 14/1.7 | 400 | 正文、对话回复 |
| Body-strong | 14/1.7 | 500 | 列表主字段 |
| Meta | 12/1.6 | 400 | 时间、计数、标签（颜色用 fg-muted） |
| Micro | 11/1.5 | 500 | 状态点/短徽标（仅限非关键信息） |
| Mono | 13/1.6 | 400 | 代码/终端 |

规则：一屏只用 3 个字号档；正文最小 14（移动 13）；禁止 10px 正文；中文标点使用全角，数字用 tabular-nums。

### 3.3 间距/圆角/影深/动效

- 间距：4pt 基础（`4,8,12,16,20,24,32,40,56`）；页面左右留白 24（窄屏 16）；区块内 12–16。
- 网格：内容列宽：对话 760px、设置 720px、其他页面 1200px（最大）；三栏 shell：侧栏 264（折叠 64）+ 主区 + 详情 360。
- 圆角：4（标签）/6（输入/按钮）/8（列表项/工具卡）/12（容器/模态）；统一，不再混用 0.75rem。
- 影深：`none | 0 0 0 1px border | 0 8px 24px -12px rgba(0,0,0,.25)`（仅浮层/弹出）。
- 动效：120ms（hover/状态）/180ms（展开/折叠）/240ms（面板进出）；easing `cubic-bezier(.2,.7,.2,1)`；
  只对 `opacity/transform/height` 做动画；`prefers-reduced-motion` 全部降为 0。

## 4. 布局与注意力架构

### 4.1 App Shell（单窗口）

```
┌ 64/264 侧栏 ┬─────────── 主内容（max 1200）───────────┬ 360 详情（可收起） ┐
│ 品牌(小)    │ 页头：标题 + 当前状态 + 主操作（右侧）   │ Tabs: 步骤/产物/上下文│
│ 导航 5-6 项 │ 内容区：唯一滚动区，按"块"分段          │ 无内容时自动隐藏      │
│ 会话列表    │                                        │                      │
│ 底部：用户  │ composer 固定底部（仅对话页）           │                      │
└─────────────┴────────────────────────────────────────┴──────────────────────┘
```

- 侧栏：品牌区只留 logo + 产品名（10px 辅助文案可删）；导航项 32px 高；会话区与导航之间用 1px 分割线；
  会话行：状态点 + 名称 + 时间（hover 出操作），最多 20 条 + 已完成折叠。
- 主区页头：**只允许一行**：左标题（H1）、右侧主操作；不要"标题 + 副标题 + 描述 + 统计"堆叠。
- 内容块：块与块间距 24–32；块内标题（H2）+ 内容；禁止块套块套块。
- 详情栏：默认收起；有工具/产物/审批时自动展开（宽屏）；窄屏改为底部抽屉。

### 4.2 每页的"一个主角"

| 页面 | 主角 | 支撑信息 | 默认隐藏 |
|---|---|---|---|
| Agent 对话 | 当前这轮回复/正在做的事 | 工具过程、上下文、产物 | 历史轮次、参数细节 |
| 设置 | 当前分组表单 | 说明文字、示例 | 高级项（折叠） |
| 信息中心 | 未读/待处理条目列表 | 来源、时间、分类 | 已归档、已读历史 |
| 机会雷达 | 推荐机会卡片（Top 3） | 匹配理由、截止时间 | 全部列表/筛选器（收起） |
| 日历 | 本周课表/日程 | 冲突提示、来源 | 设置、例外 |
| 画像/成长 | 一个主指标 + 趋势 | 明细表 | 全量历史 |

### 4.3 对话页时间线（视觉规格）

- 用户消息：右对齐，`surface-2` 底，最大宽 70%，圆角 12，无头像。
- Agent 回复：左对齐，无气泡（直接正文），行宽 72ch 内；末尾操作（复制/重试）hover 显示。
- 思考行：一行 12px muted "思考 · 3s" + chevron；展开为 `surface-2` 块，行高 1.7，最多 320px 滚动。
- 工具卡：`surface-1` 边框 + 左 2px 状态条（进行中 accent / 成功 success / 失败 danger）；
  上行：16 图标 + 13 动作名（中文动词短语）+ 状态点 + 右侧耗时/chevron；下行（展开）：参数 1–2 行、结果摘要、来源链接。
  同一轮多个工具纵向排列，间距 6px，不嵌套卡片。
- 压缩/错误/审批：统一"行内条"样式（`surface-2` + 状态色左条），不使用大卡片。
- 轮次收尾：一行 12px muted "完成 · 12 步 · 34s" 可展开；下面才是下一轮。
- 产物：文件行（图标 + 文件名 + 大小/格式 + 预览/下载按钮），点击右侧栏预览。

## 5. 组件视觉规格（关键项）

- **按钮**：高度 28/32/36（sm/md/lg）；primary=`accent` 实底白字；secondary=边框；ghost=无底 hover surface-3；
  destructive 红字描边。禁止渐变按钮。
- **输入/下拉**：高 32/36；边框 `border-strong`；focus 2px accent 环；placeholder `fg-subtle`。
- **列表行**：高 32–40；主字段 14、次字段 12 muted；hover surface-3；选中 accent-weak + 左 2px accent。
- **卡片**：仅用于独立对象；内边距 16；标题 14/600 + 可选右侧操作；卡片内不再放卡片（用分割线/块）。
- **标签/状态**：胶囊 22px 高、12px 字；成功/失败/进行中/暂停四态；颜色仅文字+浅底。
- **Tabs**：下划线式（选中 2px accent），不用胶囊堆。
- **设置行**：左 label 13/500 + 可选 desc 12 muted（最多一行），右侧控件；分组间 24px + 1px 分割线。
- **空状态**：图标 24 + 一句主文案 14 + 一句辅助 12 + 一个主操作；不放大插画。
- **Toast/Banner**：底部或内容顶部一行，最多 2 行；错误必须包含"下一步"。
- **图表**：单色系（accent + 2 个灰阶），不用彩虹色；网格线极淡。

## 6. 中英排版与文案

- 字体栈：`Inter, "PingFang SC", "Noto Sans SC", "Microsoft YaHei", system-ui`；中文行高 1.7。
- 数字：`font-variant-numeric: tabular-nums`；时间/计数右对齐。
- 文案：动词开头、短句、避免"智能/赋能/一键"等营销词；状态文案给行动（"已暂停 · 恢复/调整预算"）。
- 标题层级：页面标题 1 个；不出现两个 20px+ 标题同屏。
- 图标：Lucide 16（正文）/20（导航）；不用 emoji 做图标。

## 8. 视觉 QA 清单（每次 UI 改动必过）

1. 一屏是否只有一个主视觉焦点？缩到 50% 看是否还能看出重点？
2. 层级是否 ≤3 档？是否存在 10/11px 正文？
3. 是否出现无意义卡片套卡片/大渐变/glow/emoji 图标？
4. 浅色与深色是否用同一语义 token？对比度是否 ≥4.5（正文）/3（大字）？
5. 键盘 Tab 是否可达所有操作？focus 是否可见？
6. 1440/1280/1024/768 四档是否均无横向滚动、无内容挤压？
7. 动效是否可被 reduced-motion 关闭？是否只动 opacity/transform？
8. 状态文案是否告诉用户下一步？

## 10. 当前页面盘点与差距（待逐页细化）

- **对话页**：功能最全但控件密集；composer 一行 8+ 个控件（附件/权限/模型/思考/上下文/发送），需分组为
  "输入区 → 工具条（附件/权限）→ 模型区（模型/思考）→ 状态条（上下文/token/首 token）"两层。
- **设置页**：单列长表单，分组间缺视觉分隔；应改为"左侧分组导航 + 右侧内容"（同窗口内）。
- **信息中心/雷达/日历/画像**：目前是"信息全摆出来"的清单式页面，需按"一个主角 + 支撑信息"重排；
  卡片数量减半，用列表行 + 状态点替代。
- **侧栏**：导航+会话+品牌挤在一起；应精简品牌区、会话区加分割与搜索、底部用户区收拢。
