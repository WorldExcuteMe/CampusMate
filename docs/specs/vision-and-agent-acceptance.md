# 大图租约故障与真实平台综合验收

基线：94b475a；用户要求主代理修复大图核验25分钟卡住，并按Personal Campus Agent初衷设计全面提示词，在内部浏览器+真实CampusMate+真实API逐项验收，发现问题即修复重测。用户提供的旧规划作产品背景，不替代本轮授权。

## 事实与反证

- 原任务6668776d…，图片1082582字节（数据库base64约1443470字符）；21次认领、attempt20/max3、LLM请求0，已超10分钟预算。仓库外 `vision-stall-repro.mjs` 实际退出1，输出 `FAIL: repeated claims exceed max attempts; no model request after task wall budget`。
- 排序假设：H1认领RETURNING整行图片在60秒租约内搬运，返回时租约失效；H2准备历史/保存时多次回传图片进一步放大耗时；H3自动重认领不检查上限导致无限循环。模型推理慢被零请求推翻。另一个名含worker的进程实为Codex CUA工具，不能误当第二个CampusMate Worker而停止。
- 临时停止旧Runtime自动认领，API保持可读，原任务与图片保留。仅按实际Windows脚本PID重启，不动WSL、认证、Key、main或其他服务。

## 设计与不变条件

1. 认领仅返回状态字段，执行器启动心跳后按task+owner读取原图；执行入口仍持有原图。创建/去重/保存/完成不回传大字段，写入原始内容不丢失。
2. 历史可显式只读文本，SQL侧移除图片base64，默认完整历史契约保留。当前图片只加载一次；后续图片问题的上下文能力需真实追问验证。
3. 过期且重认领次数耗尽时原子暂停并发needs_input，不能无限queued/running。手动恢复递增attempt以隔离旧执行，允许一次新的明确恢复，保留后续对话409约束。
4. 心跳按owner/attempt/未过期租约核对，旧attempt不能续期。准备耗时计入执行预算；不通过无限放大租约或关TLS掩盖问题。
5. 机械回归负责并发/SQL契约；产品验收只认内部浏览器中真实模型、真实云数据、可见执行和持久结果。不能把fixture或脚本调用替代UI验收。
6. 实测纠正：第一次P01虽不再重复认领，但准备142秒、更新状态仍通过getTask完整读取图片，整体9分43秒仍未交付，判失败并在UI取消。修正updateTask前置读取为metadata；API提交成功后使用按owner+task隔离的24MiB/32条/10分钟输入缓存，当前请求不从数据库下载自己的上传。缓存未命中仍按owner查原图，冷启动开销不能隐瞒；不压缩或修改原图来换取测试通过。
7. 增补图片真实性提示：通知图片先提取图上声明，再核对主办官网；AI生成标记与赛事真假分开。第一次真实搜索偏向图片鉴别教程，保留为语义反例，不把普通工具成功计为通过。
8. 第二次真实高思考P01（9757648b…）准备约7秒，但3轮研究仍达约9分钟，且输出“域名失败+过期+AI水印证明虚假”、因候选网址失败而验收失败。判为失败，不能以租约bug已消失收口。新增短图片核验阶段：一次轻量只读提取，后续研究保留用户high偏好，只传图片声明文本；有实际来源后独立轻量摘要，不执行摘要工具；没有同名、同年度通知/辟谣证据时以保守模板明确尚未核实，不接受模型臆断。声明是模型提取的外部数据，不进入身份记忆。原图和CP可恢复，提取失败保留原图路径，真实预算与遥测计入额外调用。

## 影响面（基线定位）

P02实测再补：不附图追问准确返回字段，但再次读取/提取原图并走研究请求，造成额外等待，且真实性模板覆盖了用户的离线提取问法。改为从同会话已提交的最新图片声明复用，明确禁止联网的短图问答使用无工具轻量摘要；新上传图片和没有提取记录的历史图仍正常读取原图，不跨会话复用。

P04实测硬失败：e6976914…用户明确要求信息中心，模型实际save_opportunity写入雷达并宣称“信息中心（机会雷达）”，Inbox页面0条。沿用现有inbox_items结构、RLS和前端，增加云端save_to_inbox执行适配；owner只来自认证任务上下文，稳定ID防跨任务重复，原文及提取来源保留，未知字段不补写，先保存为待确认。禁止用save_opportunity替代信息中心。内存和PG契约一致，不做数据库迁移，不改原用户数据。

4b5bed76…恢复后正确调用save_to_inbox，但传入2026-11-22T18:00:00，无时区，被过严格式校验拒绝；随后真实AMD429。兼容这种明确ISO的本地时间，按当前校园默认北京时间补+08:00，日期/时间有效性仍严格检查，相同瞬间的Z/+08写法使用同一幂等ID。不会根据模糊自然语言猜截止日期。

真实429下的反证：设置页32-token文本连接成功，而Agent有短请求失败，不能推断端点整体离线。候选假设包括临时GPU容量波动和大输出预留的服务端准入开销；后者尚未证明。常规自动短问将输出预留从8192收紧到2048，离线图片字段摘要512；明确高思考和规划/写作/核验保留原预算，不以此宣称解决上游容量问题。实际请求预算与上下文遥测一致，仍按有限重试和期限停止。

P02恢复真实成功后又发现：GFM把www.caai-contest.cn后的“（图片声称）”算入域名，生成了错误Punycode目标；成功任务面板仍展示旧429，因JSON快照省略undefined字段后浅合并保留error。分别在Markdown AST层只修隐式链接的中文标点边界（保留显式中文路径、代码和安全URL守卫），以及权威任务快照显式清空缺失的error；补可红回归并刷新真实页面验证。

P04页面字段审查推翻仅按工具成功的判断：71463d97…原文明确本地18:00，模型写18:00Z，晚了8小时。通知工具新增deadlineTime（北京时间HH:mm）；服务端从当前用户原句优先、通知原文次之，核对同一日期唯一明确时分，构造+08:00，不能由模型误加Z改变时刻；明确UTC/偏移的原文不重解释。相同标题/截止日/地点的待确认通知复用既有记录，依据明确原文更正时分只更新deadline，保留原文和用户确认状态；已确认条目不自动覆盖。未知/多个冲突时分不猜。本轮只校正验收数据，原用户课表和历史不改。

P06真实研究硬失败：身份约束正确，但草稿无依据声明免费、往届已结束/下一届未报名。工具原始query正确，检索主题抽取却把“2026 蓝桥杯 报名时间 官网”的focus选成“报名时间”，精确回退删掉比赛名，返回高考报名页；天梯赛同理，Kaggle英文实体没有过滤。修复杯/赛短名、英文实体和通用查询后缀抽取，回退保留命名实体。另一次web_fetch的Kaggle正文只有39字符标题（空JS body），不能当已读规则：抓取只提取body正文，空body明确未取得正文且不建立事实来源。普通HTML片段/短真实正文仍可读，不以固定字数封杀短通知。先修链路再做真实复测，不把模型记忆或网页标题当来源。

同时补零正文守卫：明确要求官方/来源的研究，在本轮确实检索/读取但没有任何成功正文时，不能把模型最终文本中的费用、报名状态作为成果；流式草稿同样缓冲，避免先泄出确定错误再改口。保留真实失败和未核实结论。无新检索的同会话追问仍可直接用已读材料。该守卫不宣称完成语义事实核验，也不能替代每个赛事分别读取来源；这些仍需P06/P09实测。

P06再次实测：已读蓝桥杯300元且正确判0预算冲突，Kaggle费用/报名改为未知；但自由回答末尾仍凭空概括“2027正文尚未发布”等。新增多赛事个性化推荐的独立依据摘要阶段：只给当前真实正文、系统身份约束和用户直接陈述，隔离旧助手结论；输出限定JSON卡片，名称须在对应正文中，费用/报名/资格等只显示逐字可回查的原文引用，缺字段标未核实，不接收额外叙述字段。预算冲突从原文金额与最新显式预算计算，建议与事实分开。来源不足先提示执行器换可读官网/高校来源一次，再有界交付已有依据与明确缺口，不无限重试。该阶段保留真实模型、用量、工具、检查点、恢复与预算；不是虚拟答案或伪造引用。它不替代来源权威性和每项实体的真实UI审查。
