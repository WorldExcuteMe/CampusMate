## 3. Data-flow audit

Sessions are React context + localStorage (`sessions-context.tsx`, `sessions.ts:44-58`), not react-query; `use-cloud-sessions.ts:114` polls `/v1/sessions` + history page/changes every 5s (visibility-gated), 30-item cursor pages, `totalTokens` aggregate. react-query covers providers, profile, `/v1/local-workspace`, approvals, artifacts only.

Tasks: `createTask` POST `/v1/tasks` (`api-client.ts:53-56`), then `subscribeTask` (`api-client.ts:138-206`) uses `EventSource /v1/tasks/:id/stream?token&after=seq`, seq-gap repair via `/events`, 1.5s polling fallback, 5s SSE reconnect, terminal-status finish. Reload recovery `use-task-monitor.ts:16-36` lists `/v1/sessions/:id/tasks` and re-subscribes. Browser fallback `runChat` (`chat.ts:419-560`) streams tool/LLM activity into in-memory `taskViews`. Present fields: `promptUsage`, `modelConfig`, `modelRuntime.lastRequest` (reasoning requested/effective/reason, cacheRead, inputTotal/output/reasoning/costUsd, TTFT/attempts), `usage`, `budget`, `result.artifactIds`/`completion.checks`, `historyRevision`, `turnSeq`, events (`tool.called/result`, `llm.request/delta/response`, `step.*`, `checkpoint.written`, `tool.approval_requested`, `task.needs_input`). Missing for the UI: reasoning/thinking text, tool args + terminal command/stdout in events, workspace file listing, artifact metadata list, skills/manifest catalog, prefix-cache/telemetry payloads (backend has them per `docs/specs`, frontend ignores generic payload), per-task workspace/permission identity, approvals embedded in task, message-level step grouping, session-level cache/cost aggregate.
