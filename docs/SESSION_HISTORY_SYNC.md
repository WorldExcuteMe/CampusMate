# 会话历史分页与增量同步

新浏览器首次显示最近30组记录，普通任务一组包含用户请求及助手结果；旧消息点击“加载更早消息”逐页取回，不截断数据库里的历史。加载旧页保留可见消息锚点，不跳回底部。已加载页面可在同账号本机缓存中恢复。

## API与查询范围

- `GET /v1/sessions/:id/history/page?limit=30&before=<cursor>`：按稳定排序键取更早页面。页大小1至50组，返回items、before、hasMore、after和服务端累计用量。
- `GET /v1/sessions/:id/history/changes?after=<cursor>&next=<optional>`：只返回变化的任务/独立消息/只读导入记录。返回next时继续消费同一窗口，全部消费前不推进watch游标。
- 所有读取检查JWT、预期账号、session owner与删除墓碑。游标绑定账号和会话，不能跨会话复用。公开投影不含模型私有思考、工具中间消息或任务输入哈希。
- PostgreSQL按user_id+session_id查找；历史查询先分页元数据，再读取有限组的正文。不再为了读一个会话而取回账号全部任务。任务面板仍最多读取40项执行状态，不把未加载的历史任务插成孤立回复或重复计量。
- 每5秒的轮询改为增量历史，未变化时不重写整个本地会话缓存。侧边栏只同步轻量会话元数据。旧`/history`端点保留给历史兼容/一次性旧缓存导入，不用于新界面周期轮询。

## 为什么不是只用时间戳

加性迁移`20261116090000_campusmate_history_paging.sql`给任务、独立消息及legacy_history加64位事务戳和索引。使用`txid_current()`，游标以读快照的xmin为安全下界、xmax为当前分页窗口上界。先启动却后提交的事务不能被跳过；相同时间戳和时钟回拨不影响变化发现。长事务可能导致安全重叠重传，前端按组键/版本幂等合并；不宣称网络exactly-once。

触发器只记录事务戳，不增加会话父行锁，避免与现有“先锁会话再锁任务”的事务制造反向锁序。旧记录保持戳0，通过历史页可达；未改写或删除旧正文，未放宽RLS。需先应用迁移，再部署更新的API；只更新前端不能给旧后端增加此接口。

旧页和增量同时到达时，按版本拒绝陈旧结果，旧页不覆盖累计用量/增量游标；新发送的未确认轮次和本地只读历史不被快照吞掉。游标失效时重新加载最近页，不回退到反复取全历史。行政直接硬删任务/改写历史及跨设备未发送草稿同步不属于此协议。

## 验证入口

```text
npm run test:history-sync
npm --prefix backend test
npm --prefix web test
```

`test:history-sync`要求本地Docker数据库运行且迁移已应用，创建随机临时账号：真实Postgres/API下分页恢复75轮、提交顺序颠倒及相同/回拨时间戳更新、游标隔离；结束删除测试账号和级联测试记录。不请求模型，不读个人聊天。

Runtime浏览器集成增加80轮分页用例：最近30轮、分页与增量并发、累计token不倒退、不出现孤立回复、滚动锚点、记录完整性与不走周期全量端点。测试使用独立回环端口和脚本模型，不代表云端部署或三人跨电脑环境已验收。
