## 推荐提交方式：分支 → 检查 → commit → push → PR

以下为给操作者执行的命令，本交接没有替你执行 switch/add/commit/push。

### 1. 建分支，检查整批改动

在 PowerShell 执行：

```powershell
Set-Location -LiteralPath 'E:\学习\CampusMate'
git switch -c fix/local-integration-20261114
git status --short
git diff --stat
```

确认这些累计修复都属于本次提交。如果要拆为多个 PR，应先按范围整理文件和混合 diff，不要只选最后几个文件，否则可能缺依赖、类型或迁移。

### 2. 确认范围后暂存并复查

```powershell
git add -A
# 这个历史上已被 Git 跟踪的测试状态文件，即使在 .gitignore 中也要从暂存区撤出。
# 只撤暂存，不删除本地文件或丢弃内容。
git restore --staged -- web/test-results/.last-run.json
git diff --cached --stat
git diff --cached
```

必须提交源码、测试、依赖锁文件、配置模板、SQL 迁移和启动脚本；不提交真实 .env、.providers.local.json、.local、node_modules、dist、test-results、解密数据库/群消息和账号密码。若看到不该上传的文件，先用 `git restore --staged -- <精确路径>` 撤暂存并修正忽略规则，不用删除工作文件。

### 3. 检查确认后提交、推送分支

```powershell
git diff --cached --check
git commit -m "fix: stabilize local auth, agent UX and data persistence"
git push -u origin fix/local-integration-20261114
```

如果多人又更新了 main，应先保留本地提交，再 fetch/合并或 rebase 新 main 并重新验证；遇到冲突停下处理，不用 reset --hard，不 force push 主分支。推送若无写权限，使用个人 Fork 和跨仓库 PR，不改原仓库权限或泄露令牌。

### 4. 回到 GitHub 创建 PR

从 fix/local-integration-20261114 提交到 main，请另一个成员审查后合并。不要直接 push main。PR 概要可使用下方模板；不要把本机账号、密码、模型密钥、连接串放进 PR 描述或截图。

```text

内容：
- 同步上游后保留本地兼容修复，补本地 Docker 开发/验证脚本。
- 注册登录、会话/账号数据隔离；任务交互、进度、Markdown、操作提示。
- 北京时间时效管理、通知聚类修复及群同步账号作用域隔离。

验证：web 199 单测、22 E2E、build；backend 199 通过/1 外部 PG 跳过；迁移 19/19；本地真实 Auth/RLS/核验 SQL 验证。
```
