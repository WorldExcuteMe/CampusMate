# CampusMate · PRODUCT_SPEC.md

版本 0.1 · 2026-11-12 · 来源：主提示词（本地存档）· 状态：MVP 基线，变更需先更新本文件

## 1. 产品定位

面向大学生的智能信息管理、机会发现、可信度核验与个人成长规划 Agent。核心链路：

Information → Understanding → Discovery → Matching → Verification → Decision → Planning → Action → Growth

不等于 Notion / Todo List / 普通聊天机器人。解决：信息过载、优先级不明、机会价值不明、真伪不明、缺个性化匹配、不知如何准备、成长经历缺管理。

## 2. 开发约束与禁止项

约束：三人异地协作；无硬件依赖；面向普通大学生；Web 优先；MVP 优先；不自建大模型；不做复杂微服务；不把所有业务交给大模型；重要信息与推荐必须有来源依据；适合公开演示与评审。

禁止：未授权读取 QQ/微信私聊；自动登录第三方招聘站；自动投简历；自动报名竞赛；自动付款；伪造官方信息；把「没找到」说成「不存在」；把「无法核验」直接判为诈骗；用虚构数据冒充真实业务结果。

## 3. 四大模块

### A. Campus Inbox（智能信息收件箱）
- 输入：粘贴文本、聊天截图（png/jpg）、PDF、DOCX、公开网页 URL。
- 提取字段：标题、类别、发布组织、摘要、截止时间、参与条件、所需材料、参与成本、地点、原始 URL、原文证据、提取置信度。
- 分类：必须处理 / 高价值机会 / 值得关注 / 普通信息 / 风险警告。
- 优先级与个人匹配度**分开计算**；优先级考虑截止时间、重要程度、是否需行动、当前任务负载。
- 用户审核：AI 提取后必须展示结构化结果，用户可确认/修改/忽略/收藏/生成待办；**不得未经确认批量创建任务**。

### B. Opportunity Radar（机会雷达）
- 类别：学科竞赛、实习招聘、科研项目、奖学金、校园活动、开源项目。
- 统一机会模型：唯一 ID、标题、类型、主办方、描述、参与条件、截止时间、来源 URL、来源类型、采集时间、信息状态。
- 匹配：先硬性资格过滤，再软性匹配；初始权重 兴趣 25% / 技能 25% / 发展目标 20% / 时间预算 15% / 背景经验 15%（**可配置**）；结果附可解释理由。
- 操作：收藏、忽略、详情、匹配理由、发起核验、创建参与计划。

### C. Trust Engine（可信度核验）
- 对象：企业、岗位、竞赛、科研、奖学金、活动。
- 内容：主办方身份、官方来源、招聘主体、域名、报名要求、收费要求、截止时间、参与资格、多源一致性。
- 状态：VERIFIED / PARTIALLY_VERIFIED / UNVERIFIED / CONFLICTING / RISK_FLAGGED。
- Evidence 必含：sourceUrl、sourceType、excerpt、retrievedAt、supports、confidence。**禁止无来源支持的核验结论**。

### D. Growth Center（成长与行动）
- 画像：专业、年级、兴趣、技能、发展目标、时间预算、参与经历。
- 目标：竞赛/实习/科研/技能提升/个人成长。
- Action Planner：准备阶段、子任务、时间安排、任务依赖、截止日期、预计投入。
- 操作：确认/修改计划、创建/完成/调整任务、查看进度。
- 成长档案：完成的项目/竞赛/科研/实习，**用户确认后才成正式记录**。

## 4. 页面清单（13）

Landing、Authentication、Onboarding、Dashboard、Inbox、Inbox Detail、Opportunity Radar、Opportunity Detail、Trust Report、Growth Center、Task Detail、User Profile、Settings。统一侧边栏导航；简洁现代、面向大学生、不做企业后台风、不抄 Notion、不堆卡片；截止时间突出、风险提示明显、操作有反馈；桌面优先、移动可用。

## 5. Demo Mode（比赛演示必备）

无需注册体验预设数据；Demo 与真实用户数据隔离；Demo 不得修改真实数据；支持完整浏览与预设 Agent 处理过程展示；Mock 结果明确标识，不得伪装为实时检索/真实模型结果。

预设：1 个虚拟大学生档案 + 5 条校园通知 + 3 个竞赛 + 2 个实习 + 1 个科研 + 3 个待办 + 1 份核验报告。

## 6. 第一条业务闭环（MVP 起点）与验收

链路：上传校园通知 → 文本解析 → AI 提取 → 信息分类 → 优先级判断 → 用户确认 → 保存 Inbox → 生成待办 → Dashboard 展示。

验收（10 条，全部需证据）：
1. 用户能输入一条通知文本。
2. Agent 提取标题、类别、截止日期。
3. 提取结果通过 Schema 校验。
4. 用户可修改提取结果。
5. 用户可确认保存。
6. 用户可创建任务。
7. 任务在 Dashboard 显示。
8. 刷新后数据仍在。
9. 操作有错误反馈。
10. 单元测试与核心 E2E 通过。

无真实模型 API 时先用**明确标识的 Mock Provider** 跑通闭环。

## 7. MVP 范围与非目标

MVP：四模块基础交互 + Demo Mode + 第一条闭环 + 核心测试 + Sites 公开 Demo。
非目标（第一版不做）：全网爬虫、自动报名/投递/付款、移动端原生 App、复杂微服务、自建模型、实时 IM 集成。
