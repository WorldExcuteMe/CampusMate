# CampusMate 计算工具与通用Agent能力评估

结论：Word/PDF写作不必先给模型任意终端。当前结构化文档、可信生成器和导出检查已经支持正文、表格、图片、图表与引用。模型负责组织内容，服务端负责生成文件并核对实际结果；这种能力可独立于用户电脑部署。

需要分析原始表格、统计实验、模拟、绘图或批量数据清洗时，可以再增加隔离的Python/JavaScript计算后端。现有Local Companion属于用户授权的本机能力，受路径/命令/群组范围和审批限制，不能改名作为云沙箱。Node vm也不能作为不可信代码的安全边界（官方：https://nodejs.org/api/vm.html）。本轮没有注册compute能力或放置无实际后端的执行按钮。

拟接入契约：ComputeRequest包含ownerId、taskId、requestId、language、code、只读inputArtifactIds、outputKinds和limits；ComputeResult包含status、脱敏stdout/stderr、用量、输出artifactIds及失败原因。身份由服务端提供，不能采信模型自填owner/任意宿主路径。输出继续复用当前ArtifactStore版本、哈希与授权下载。

部署前需要一个真实隔离后端，例如受限容器/微虚拟机：非root、无宿主挂载、只读根文件系统、临时工作目录、默认无网络、明确包白名单、CPU/内存/进程/文件/输出/总时限限制、取消后销毁，以及跨用户隔离和输出扫描。密钥不注入生成代码环境。请求重试只读取已完成requestId，不能重复未知副作用。

验收应在真实部署后验证超时/内存耗尽/进程洪泛、读取其他用户文件、元数据网络访问、环境变量泄露、恶意输出路径、取消回收和并发用户隔离，保存实际证据。单元测试和Node vm运行成功均不能替代这些验收。当前没有选定部署环境与费用，因此不声称沙箱已实现；这一范围按批准Spec只完成接口与部署条件评估。

后续优先级是先稳定检索、上下文、可见执行和文档交付，再以真实数据分析任务决定是否引入计算后端。只增加工具数量不会自动产生通用Agent能力；实际任务的规划、恢复、信息判断与交付检查仍需持续实测。
