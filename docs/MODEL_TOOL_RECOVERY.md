## 实际故障

原竞赛任务和下一条“继续”都被写成succeeded，但无tool.called事件，结果分别是多一个闭括号的JSON和Gemma原始工具控制文本。解析器漏掉两种格式，将其当最终答复；builtin Gemma全部能力unknown又导致原生工具及流式未开启。第三条“jixu”是单次模型请求180008ms超时，没有工具执行，不能与前两次混为一个网络故障。

初始最小复现两种格式均toolCalls=0、stopReason=completed、rawToolProtocolDelivered=true，退出1；修复后均toolCalls=1且取得最终观测答复。

## 改动

- 有界、纯数据解析器支持严格JSON的少量多余闭括号，以及Gemma工具token/裸键/专用字符串delimiter。不从说明文字抽取调用，不eval、不接受表达式/危险键/多个混杂命令。未知或损坏工具指令最多反馈修正一次，仍失败就明确invalid_output，不能被验收成功。所有执行仍经原工具白名单、参数、预算、授权及幂等路径。
- 原生端点偶尔泄漏的文本工具指令转换为真实tool_calls及对应观测回传。流式工具协议暂存，避免作为普通答复直接显示。JSON回退协议合入首个system，避免第二system未被端点采用。
- 已知Radeon native路径也合并稳定指令和动态日期到首条system。真实流中又发现同index不同完整ID的独立调用被拼成web_fetchweb_fetch：现以ID区分、index路由后续增量，完整ID不再拼接；SSE错误帧准确报错，[DONE]后结束读取，不等HTTP连接关闭。
- builtin与BYOK共用已知Radeon Gemma契约；图像、原生工具、SSE、输出参数和嵌套思考开关自动接线。其他端点不凭名字推断能力；未知图片允许实际请求，明确不支持时才本地拒绝。
- 超时、调用方取消、本地能力、输入限制、认证、限流、响应协议和真实网络错误分开呈现；移除所有失败都称“模型不可达，降级”的验收说明。默认180秒没有提高。
- 原Bing长查询实测返回征兵网等无关结果，模型因而误报查不到比赛。搜索现在按实体相关性过滤，必要时额外做一次精确实体查询，共用12秒期限；保留原始/实际查询和attempts，不硬编码赛事答案。
- 对普通收集任务，失败的web_fetch只有在后续2xx正文取得、最终答复引用成功URL、且原失败URL不是用户指定必读来源时，才能作为已恢复只读错误并附提示。原始失败事件、调用次数、未解决或未知历史错误、写入失败全部保留；不能泛化为忽略工具错误。
- 普通简短信息查询取得正文后转入首轮摘要阶段，撤下工具列表，按write阶段生成短摘要与来源；明确长文、复杂规划或写入任务保持原流程。防止资料已齐后仍在工具模式中无界铺陈，不靠增加默认超时解决收尾。
- 设置页移除能力下拉框，只需地址/模型/Key，ID自动生成、名称可选；编辑仍保留原Key，能力来源与未知状态可查看。
